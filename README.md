# Планирование производства

Веб-приложение для планирования производства лекарственных трав: потребность в фасовке (2 ступень)
и переработке (1 ступень), обеспеченность НФП, сырьём и упаковкой, диаграмма Ганта по линиям.
Карта проекта и согласованные правила — в документе «Карта проекта: планирование производства».

**Сейчас готово (этапы 1–4):** каркас, импорт пяти выгрузок 1С со сверкой наименований и отчётом о качестве данных,
расчёт потребности 2 ступени с выгрузкой Excel для диспетчера, календари линий и диаграмма Ганта 2 ступени.
Дальше: 1 ступень → отчёты.

## Расчёт потребности 2 ступени

Экран «Потребность 2 ступени»: горизонт N месяцев и дата расчёта → «Рассчитать» → «Скачать Excel для диспетчера».

1. План продаж на горизонт: текущий месяц — по доле оставшихся рабочих дней (производственный календарь РФ,
   `backend/app/planning/calendar.py`), следующие N−1 месяцев — целиком. Страхового запаса нет.
2. К фасовке = план − запас ГП (склад ГП + склад оптовой торговли, колонка «Доступно», без брака) − открытые заказы
   (остаток «запланировано − выполнено»), но не меньше выпуска линии за 1 ч.
   Серии из actual_items (колонки min / max): потребность не меньше минимальной серии; если больше максимальной —
   делится на несколько серий («2 сер. по 40 000»), каждая не меньше минимальной.
3. Приоритет — месяц, когда прогнозный запас ГП уйдёт в минус; при равенстве A → B → C.
4. «Можно выпустить сейчас» ограничено НФП (та же фракция, целевое назначение ГП, «Фасовка = Да») и упаковкой
   (аналоги «обычный / импорт» суммируются). НФП и общие материалы делятся между позициями по приоритету;
   если выходит меньше минимальной партии или серии — 0. Нехватка материала до 10 % от потребности дефицитом не считается
   (в списке помечена «в пределах 10 %»).
5. Дефицит НФП за вычетом карантина (5 рабочих дней) — задание для 1 ступени. Открытые заказы 1 ступени того же
   НФП и фракции показаны рядом («В заказах 1 ст.», «Не покрыто»); назначения в заказе 1 ступени нет, поэтому
   объём распределяется по строкам дефицита начиная с большей. «Выпустить» и «Не покрыто» округляются до 100 кг.

**СТМ.** Продукция под торговой маркой клиента (колонка «СТМ» да/нет в actual_items; если её нет или ячейка
пустая — по наименованию с «ТМ "Будь здоров!"», `backend/app/reference/stm.py`) фасуется только после письма клиента. Поэтому план продаж по СТМ — прогноз,
а не задание: СТМ идёт после всех наших позиций (получает остаток НФП и упаковки), не входит в сводку, дефицит
материалов и задание 1 ступени и показана на отдельной вкладке «СТМ — по письму клиента» и листе Excel.
Заказ СТМ, поставленный в 1С по письму, на графике выделен фиолетовым и встаёт раньше наших автоматически
расставляемых заказов (после начатых и ручной очереди).

В Excel листы: «К фасовке», «Дефицит материалов», «Дефицит НФП (1 ступень)», «СТМ (по письму клиента)», «Все позиции», «Все материалы», «Параметры».

## Склады

Раздел «Склады» показывает, как каждый склад из отчёта «Остатки по складам» участвует в расчёте, и позволяет
поменять роль: ГП на сертификации, ГП к продаже, НФП для фасовки, НФП на карантине, ПП, сырьё, упаковочные материалы
или «не учитывается». Роли по умолчанию — в `backend/app/reference/warehouses.py`. Новый склад, которого там нет,
не учитывается, пока ему не назначат роль; импорт выдаёт об этом предупреждение. Строки «(отход)» в материалы
не попадают. Какие склады учтены, видно на экране «Потребность 2 ступени» и на листе «Параметры» в Excel.

## Календари линий и Гант 2 ступени

**Календари линий.** У каждой линии шаблон: «5/2» (смены в рабочие дни производственного календаря РФ) или «24/7»
и число смен в день (по умолчанию 5/2, одна смена). Любой день меняется вручную — клик по клетке (0 → 1 → 2 → 3 смены),
Shift+клик возвращает день к шаблону. Смены: 1 — 08:00–16:00, 2 — 16:00–24:00, 3 — 00:00–08:00.
Над календарём — сводка по группам линий: сколько они выпустят по месяцам при таком графике (часы × норма)
и сколько предстоит выпустить (остаток открытых этапов + потребность к фасовке из последнего расчёта) с % загрузки.

**График производства.** «Загрузить заказы из 1С» берёт открытые этапы 2 ступени по номерам этапа 1С
(КЛ00-1739.1.1): новые добавляются, изменённые обновляются, исчезнувшие из выгрузки (завершённые) убираются.
В расчёт идёт остаток «запланировано − выполнено» — время этапа считается только на невыпущенное количество;
полностью выполненные этапы не показываются. Очередь на каждой линии:

1. этапы со статусом «Начат» (▶) — первыми на линии из 1С, в порядке фактического начала; их линию и место
   поменять нельзя, перед ними ничего не встаёт;
2. очередь, заданная вручную (📍), — в заданном порядке;
3. остальные — по приоритету из последнего расчёта потребности (раньше кончится ГП → раньше фасуем),
   на линию своей группы, где закончатся раньше.

Длительность = количество / выпуск линии в час + 1 ч переналадки, если до него на линии был другой продукт
(начатый этап первым на линии — без переналадки). На ночь и выходные этап «замирает», но другой в его середину
не встаёт.

Страница разбита на вкладки:

- **Диаграмма Ганта** — как «График этапов производства» в 1С: строка линии со сводной полосой этапов
  (бордовым — переналадка), под ней строки этапов; полосы разбиты по рабочему времени. Этап можно перетащить
  по времени в его строке — он встанет в очередь линии на то место, куда его бросили;
- **Очередь по линиям** — карточки этапов по линиям; перетаскивание меняет порядок или переносит этап на другую
  линию той же группы (есть и стрелки ↑↓). Как только очередь линии поменяли, она вся становится ручной;
  кнопка «Авто» возвращает линию на расстановку по приоритету;
- **Заказы** — таблица этапов: статус 1С, остаток, месяц, когда кончится запас ГП, линия (выбор линии ставит
  этап в конец её очереди), сроки и предупреждения.

Предупреждения у заказа: ГП с учётом сертификации (7 дней) будет доступна позже месяца, когда кончается запас;
НФП к старту не хватает. Этап сначала берёт НФП, зарезервированный диспетчером при оформлении этапа (на складе НФП
или на карантине), затем свободный с «Фасовка = Да», затем свободный с карантина — если этап начнётся после
его окончания (5 рабочих дней). Начатые этапы НФП уже получили: их не проверяем и из остатка не вычитаем;
заказ не помещается в горизонт 180 дней.

## Запуск на своём ПК (Docker Desktop)

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустите его.
2. В папке репозитория выполните:
   ```
   docker compose up -d --build
   ```
3. Откройте http://localhost:8090 → «Загрузить из папки «Исходные данные»».
   Порт меняется без правки файлов: создайте рядом с `docker-compose.yml` файл `.env` со строкой `APP_PORT=9000`
   и перезапустите `docker compose up -d`.

Новые выгрузки из 1С кладите в папку `Исходные данные` с теми же именами файлов (или загружайте кнопкой
«Выбрать файлы…»). Каждая загрузка сохраняется отдельным снимком; старые снимки остаются.
Данные хранятся в PostgreSQL в томе Docker `pgdata` и переживают перезапуск.

Остановить: `docker compose down` (данные сохранятся). Обновить после изменений кода: снова `up -d --build`.

## Разработка без Docker

Нужны Python 3.12+ и Node.js 22+. По умолчанию БД — файл SQLite `planning.db` в корне репозитория.

```
cd backend
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload          # API: http://localhost:8000/docs

cd ../frontend
npm install
npm run dev                            # интерфейс: http://localhost:5173
```

Проверить выгрузки из командной строки, без сервера:

```
cd backend
python -m app.cli check                # ошибки и предупреждения
python -m app.cli check --all          # плюс информационные сообщения
python -m app.cli import               # то же + сохранить снимок в БД
```

Тесты идут на реальных файлах из `Исходные данные`: `cd backend && pytest`.

## Как устроен импорт

| Файл | Что берём | Правила |
| --- | --- | --- |
| `actual_items.xlsx` | 129 ГП: ABC, масса, группа линий, форма, НФП, целевое назначение, печатный материал | Розлив и контрактная площадка не планируются (122 позиции в расчёте) |
| `Остатки по складам.xlsx` | 7 складов: серия и срок годности, характеристика (фракция), целевое назначение, «Фасовка», в наличии / резерв / доступно | Запас ГП = склад ГП + склад оптовой торговли ЛС; строки «(брак)» исключаются |
| `Ресурсные спецификации.xlsx` | Нормы на 1 000 шт. ГП / 1 000 кг НФП | Только «Действует»; из нескольких действующих версий — с максимальной нормой НФП; материалы-аналоги (обычный/импорт) взаимозаменяемы |
| `План продаж *.xlsx` | Помесячный план | Файлы склеиваются в одну ленту; строка «Итого» пропускается |
| `Список активных заказов*.xlsx` | Этапы производства 1 и 2 ступени: номер, статус, спецификация, подразделение, основной ВРЦ, фактическое начало, запланировано, выполнено (только 2 ступень) | Открытые заказы в расчёте, Гант по номеру этапа; линия ВРЦ → код линии (`line_from_1c`) |

ГП связывается со спецификацией по точному имени, затем по имени без различий в написании
(«20*2.0г» = «20х2,0г», ®, латинская «o»), затем по печатному материалу (Б-6М, П-8), затем по похожему имени
(такую связь нужно подтвердить).

## Структура

```
backend/
  app/importers/   парсеры отчётов 1С, сверка имён, отчёт о качестве
  app/reference/   линии, мощности и правила планирования
  app/planning/    производственный календарь и расчёт потребности
  app/exporters/   Excel для диспетчера
  app/scheduling/  календари линий и расстановка заказов (Гант)
  app/services/    сохранение снимков в БД
  app/api/         REST API (FastAPI)
  migrations/      миграции БД (Alembic)
  tests/
frontend/          интерфейс (React + TypeScript + Mantine)
Исходные данные/   выгрузки из 1С
docker-compose.yml PostgreSQL + API + интерфейс
```
