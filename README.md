# Планирование производства

Веб-приложение для планирования производства лекарственных трав: потребность в фасовке (2 ступень)
и переработке (1 ступень), обеспеченность НФП, сырьём и упаковкой, диаграмма Ганта по линиям.
Карта проекта и согласованные правила — в документе «Карта проекта: планирование производства».

**Сейчас готово (этапы 1–4):** каркас, импорт пяти выгрузок 1С со сверкой наименований и отчётом о качестве данных,
расчёт потребности 2 ступени с выгрузкой Excel для диспетчера, календари линий и диаграмма Ганта 2 ступени.
Дальше: 1 ступень → отчёты.

## Расчёт потребности 2 ступени

Экран «Потребность 2 ступени»: горизонт N месяцев и дата расчёта → «Рассчитать» → «Скачать Excel для диспетчера».

1. План продаж на горизонт: текущий месяц — по доле оставшихся рабочих дней (производственный календарь РФ,
   `backend/app/planning/calendar.py`), следующие N−1 месяцев — целиком. Страхового запаса нет.
2. К фасовке = план − запас ГП (склад ГП + склад оптовой торговли, колонка «Доступно», без брака) − открытые заказы,
   но не меньше выпуска линии за 1 ч.
3. Приоритет — месяц, когда прогнозный запас ГП уйдёт в минус; при равенстве A → B → C.
4. «Можно выпустить сейчас» ограничено НФП (та же фракция, целевое назначение ГП, «Фасовка = Да») и упаковкой
   (аналоги «обычный / импорт» суммируются). НФП и общие материалы делятся между позициями по приоритету;
   если выходит меньше минимальной партии — 0.
5. Дефицит НФП за вычетом карантина (5 рабочих дней) — задание для 1 ступени.

В Excel листы: «К фасовке», «Дефицит материалов», «Дефицит НФП (1 ступень)», «Все позиции», «Все материалы», «Параметры».

## Календари линий и Гант 2 ступени

**Календари линий.** У каждой линии шаблон: «5/2» (смены в рабочие дни производственного календаря РФ) или «24/7»
и число смен в день (по умолчанию 5/2, одна смена). Любой день меняется вручную — клик по клетке (0 → 1 → 2 → 3 смены),
Shift+клик возвращает день к шаблону. Смены: 1 — 08:00–16:00, 2 — 16:00–24:00, 3 — 00:00–08:00.

**Гант.** «Загрузить заказы из последнего снимка 1С» берёт открытые заказы 2 ступени по номерам: новые добавляются,
изменённые обновляются, исчезнувшие из выгрузки (закрытые в 1С) убираются. Расстановка:

- заказ встаёт только на линию своей группы — туда, где закончится раньше;
- длительность = количество / выпуск линии в час + 1 ч переналадки, если до него на линии был другой продукт;
- на ночь и выходные заказ «замирает», но другой заказ в его середину не встаёт;
- порядок — по приоритету из последнего расчёта потребности (раньше кончится ГП → раньше фасуем);
- перетащенный мышью заказ фиксируется (📌) и не двигается при перепланировании, остальные встают вокруг;
  снять фиксацию — переключатель в таблице заказов.

Предупреждения у заказа: ГП с учётом сертификации (7 дней) будет доступна позже месяца, когда кончается запас;
НФП к старту не хватает (учитываются «Доступно» + резерв склада НФП, карантин — через 5 рабочих дней);
заказ не помещается в горизонт 180 дней. Под диаграммой — загрузка линий по неделям.

## Запуск на своём ПК (Docker Desktop)

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустите его.
2. В папке репозитория выполните:
   ```
   docker compose up -d --build
   ```
3. Откройте http://localhost:8080 → «Загрузить из папки «Исходные данные»».

Новые выгрузки из 1С кладите в папку `Исходные данные` с теми же именами файлов (или загружайте кнопкой
«Выбрать файлы…»). Каждая загрузка сохраняется отдельным снимком; старые снимки остаются.
Данные хранятся в PostgreSQL в томе Docker `pgdata` и переживают перезапуск.

Остановить: `docker compose down` (данные сохранятся). Обновить после изменений кода: снова `up -d --build`.

## Разработка без Docker

Нужны Python 3.12+ и Node.js 22+. По умолчанию БД — файл SQLite `planning.db` в корне репозитория.

```
cd backend
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload          # API: http://localhost:8000/docs

cd ../frontend
npm install
npm run dev                            # интерфейс: http://localhost:5173
```

Проверить выгрузки из командной строки, без сервера:

```
cd backend
python -m app.cli check                # ошибки и предупреждения
python -m app.cli check --all          # плюс информационные сообщения
python -m app.cli import               # то же + сохранить снимок в БД
```

Тесты идут на реальных файлах из `Исходные данные`: `cd backend && pytest`.

## Как устроен импорт

| Файл | Что берём | Правила |
| --- | --- | --- |
| `actual_items.xlsx` | 129 ГП: ABC, масса, группа линий, форма, НФП, целевое назначение, печатный материал | Розлив и контрактная площадка не планируются (122 позиции в расчёте) |
| `Остатки по складам.xlsx` | 7 складов: серия и срок годности, характеристика (фракция), целевое назначение, «Фасовка», в наличии / резерв / доступно | Запас ГП = склад ГП + склад оптовой торговли ЛС; строки «(брак)» исключаются |
| `Ресурсные спецификации.xlsx` | Нормы на 1 000 шт. ГП / 1 000 кг НФП | Только «Действует»; из нескольких действующих версий — с максимальной нормой НФП; материалы-аналоги (обычный/импорт) взаимозаменяемы |
| `План продаж *.xlsx` | Помесячный план | Файлы склеиваются в одну ленту; строка «Итого» пропускается |
| `Список активных заказов 2 ступень.xlsx` | Номер заказа 1С, ГП, количество | Связь с Гантом по номеру |

ГП связывается со спецификацией по точному имени, затем по имени без различий в написании
(«20*2.0г» = «20х2,0г», ®, латинская «o»), затем по печатному материалу (Б-6М, П-8), затем по похожему имени
(такую связь нужно подтвердить).

## Структура

```
backend/
  app/importers/   парсеры отчётов 1С, сверка имён, отчёт о качестве
  app/reference/   линии, мощности и правила планирования
  app/planning/    производственный календарь и расчёт потребности
  app/exporters/   Excel для диспетчера
  app/scheduling/  календари линий и расстановка заказов (Гант)
  app/services/    сохранение снимков в БД
  app/api/         REST API (FastAPI)
  migrations/      миграции БД (Alembic)
  tests/
frontend/          интерфейс (React + TypeScript + Mantine)
Исходные данные/   выгрузки из 1С
docker-compose.yml PostgreSQL + API + интерфейс
```
